# Требования к системе Surround View

## 1. Назначение документа

Документ фиксирует проверяемые требования к программному комплексу магистерской работы. Требование считается выполненным только при наличии реализации, теста или измерительного протокола.

## 2. Область системы

Система состоит из следующих объектов:

| ID | Объект | Назначение |
|---|---|---|
| SYS | Программный комплекс | Полный стенд обработки и отображения |
| SRV | `sv-server` | Сбор данных, GPU-обработка и выдача результата |
| UI | `sv-ui` | Qt5-интерфейс головного устройства |
| SIM | `sv-simulator` | Моделирование автомобиля, камер, сенсоров и CAN |
| PRO | Протокол обмена | Передача кадров, команд, сенсоров и телеметрии |
| CFG | Конфигурация | Описание автомобиля, камер, калибровки и рендера |
| OPS | Эксплуатационная среда | Linux, запуск, диагностика и воспроизведение |

Субъекты системы:

- `Оператор автомобиля` управляет виртуальным ракурсом через touch UI.
- `Разработчик/исследователь` задает конфигурацию, запускает стенд, анализирует метрики и записи.
- `Источник устройств` поставляет кадры камер, сенсоры и CAN-сообщения.
- `Сервер` принимает решения по синхронизации, обработке и состоянию виртуальной камеры.

## 3. Приоритеты

- **MUST** — обязательное требование минимального защищаемого результата.
- **SHOULD** — необходимо реализовать при наличии времени; отсутствие должно быть обосновано.
- **COULD** — расширение, не влияющее на завершенность MVP.

## 4. Функциональные требования верхнего уровня

| ID | Приоритет | Требование | Приемка |
|---|---|---|---|
| SYS-F-001 | MUST | Система должна работать в режимах simulator, replay и hardware adapter без изменения алгоритма рендеринга. | Один и тот же server pipeline проходит три сценария. |
| SYS-F-002 | MUST | Система должна формировать интерактивную 3D-сцену из четырех камер. | Оператор меняет ракурс, а результат строится сервером. |
| SYS-F-003 | MUST | Геометрия проекционной поверхности должна зависеть от конфигурации автомобиля и камер. | Изменение конфигурации меняет сетку без перекомпиляции. |
| SYS-F-004 | MUST | Коррекция fisheye, выборка и blending должны выполняться GPU-конвейером, кроме эталонного CPU-режима. | Профиль показывает GPU render stages; CPU используется для сравнения. |
| SYS-F-005 | MUST | Система должна предоставлять итоговый кадр Qt5 UI. | UI отображает кадр, сгенерированный сервером. |
| SYS-F-006 | MUST | Система должна измерять end-to-end latency, FPS, drops и время GPU-стадий. | Метрики сохраняются в telemetry/trace. |
| SYS-F-007 | MUST | Потеря одного входного источника не должна приводить к зависанию сервера. | Fault injection проходит с диагностикой состояния. |
| SYS-F-008 | SHOULD | Система должна записывать и воспроизводить входные данные. | Replay дает повторяемый результат с теми же timestamp. |

## 5. Ограничения MVP

В MVP входят четыре камеры, одна поддержанная модель fisheye, bowl-поверхность, базовое feathering, виртуальная orbit-камера, Qt5 UI, simulator/replay и профилирование.

В MVP не входят нейросетевые методы, SLAM, полноценная 3D-реконструкция, depth estimation, аппаратная синхронизация и сертификация ISO 26262.

## 6. Трассируемость

Каждый `MUST` должен быть связан с тестом или экспериментом. Формат идентификаторов тестов: `T-<объект>-<номер>`, например `T-SRV-004`. Результаты приемки хранить в `docs/experiments/` после появления исходного кода.
