# Требования к `sv-simulator`

## Ответственность

`sv-simulator` — приложение ноутбука для формирования воспроизводимых входных данных сервера. Оно не заменяет серверный GPU pipeline и не содержит его бизнес-логики.

## Функциональные требования

| ID | Приоритет | Требование | Приемка |
|---|---|---|---|
| SIM-F-001 | MUST | Simulator должен подключаться к серверу по публичному протоколу. | Сервер принимает данные без simulator-specific API. |
| SIM-F-002 | MUST | Simulator должен иметь управляемый 3D-мир с автомобилем. | Положение и ориентация автомобиля изменяются оператором. |
| SIM-F-003 | MUST | Simulator должен генерировать четыре camera frames с уникальным `camera_id`. | Сервер получает четыре независимых потока. |
| SIM-F-004 | MUST | Виртуальные камеры должны иметь настраиваемые intrinsics/extrinsics и FOV. | Изменение конфигурации меняет входной ракурс. |
| SIM-F-005 | MUST | Simulator должен генерировать timestamps и sequence numbers. | Пропуски и порядок видны в server telemetry. |
| SIM-F-006 | MUST | Simulator должен генерировать базовые сенсорные данные: положение, скорость и yaw/steering. | Значения соответствуют состоянию 3D-модели. |
| SIM-F-007 | MUST | Simulator должен формировать CAN frames с заданными ID, DLC, payload и периодом. | Server принимает и декодирует тестовые сообщения. |
| SIM-F-008 | MUST | Simulator должен поддерживать запись и replay исходящих данных. | Replay повторяет scenario без live 3D-управления. |
| SIM-F-009 | MUST | Simulator должен позволять задавать latency, drops и отключение источника. | Fault injection воспроизводится по сценарию. |
| SIM-F-010 | SHOULD | Simulator должен выводить debug view всех четырех виртуальных камер. | Оператор видит соответствие camera_id и ракурса. |
| SIM-F-011 | COULD | Simulator может использовать физический игровой движок. | Не является условием приемки диссертации. |

## Требования к сценарию

Сценарий должен задавать:

- стартовое состояние автомобиля;
- траекторию или управление оператора;
- параметры камер;
- частоты кадров и сенсоров;
- CAN message schedule;
- seed случайных шумов;
- fault injection;
- длительность и имя записи.

Одинаковый scenario и seed должны давать сопоставимые входные данные.

## Ограничения

- Simulator не должен выполнять финальный Surround View вместо сервера.
- Реализация 3D-мира не должна быть обязательной зависимостью `sv-server`.
- Синтетические кадры должны иметь контрольные маркеры для проверки геометрии.
