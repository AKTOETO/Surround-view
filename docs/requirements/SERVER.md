# Требования к `sv-server`

## Ответственность

`sv-server` — основной процесс на головном устройстве. Он владеет входными очередями, конфигурацией, GPU-ресурсами, состоянием виртуальной камеры и итоговым кадром.

## Функциональные требования

| ID | Приоритет | Требование | Приемка |
|---|---|---|---|
| SRV-F-001 | MUST | Сервер должен запускаться без Qt5 и графической оболочки пользователя. | Запуск как standalone-процесс или systemd service. |
| SRV-F-002 | MUST | Сервер должен принимать до четырех потоков `camera_frame`. | Каждый поток идентифицируется `camera_id` 0..3. |
| SRV-F-003 | MUST | Сервер должен принимать `sensor_sample` и `can_frame`, сохраняя их timestamp. | Тестовый simulator packet виден в telemetry/log. |
| SRV-F-004 | MUST | Сервер должен валидировать конфигурацию до создания GPU-ресурсов. | Ошибная конфигурация завершается диагностируемой ошибкой. |
| SRV-F-005 | MUST | Сервер должен генерировать bowl-сетку из параметров конфигурации. | Сетка и индексы изменяются при изменении размеров поверхности. |
| SRV-F-006 | MUST | Сервер должен преобразовывать точки поверхности в UV каждой камеры с учетом intrinsics, extrinsics и distortion. | GPU-результат совпадает с CPU reference в заданном допуске. |
| SRV-F-007 | MUST | Сервер должен смешивать валидные изображения камер по весам и нормализовать сумму весов. | Нет черных дыр в тестовой конфигурации и сумма весов проверена. |
| SRV-F-008 | MUST | Сервер должен хранить состояние виртуальной камеры централизованно. | UI получает подтвержденный `camera_state`. |
| SRV-F-009 | MUST | Сервер должен принимать `orbit`, `pan`, `zoom` и preset-команды. | Команда меняет итоговый ракурс без перерасчета входных кадров на CPU. |
| SRV-F-010 | MUST | Сервер должен выдавать `rendered_frame` и `telemetry`. | UI получает кадр и показатели состояния. |
| SRV-F-011 | MUST | Сервер должен обнаруживать timeout, пропуски и отключение источника. | Состояние источника меняется в health telemetry. |
| SRV-F-012 | SHOULD | Сервер должен поддерживать горячую замену входного adapter без изменения render pipeline. | File, simulator и hardware adapters используют общий интерфейс. |

## GPU-требования

| ID | Приоритет | Требование | Приемка |
|---|---|---|---|
| SRV-G-001 | MUST | Render pipeline должен использовать GPU textures, shaders и framebuffer. | OpenGL debug/profile capture подтверждает GPU stages. |
| SRV-G-002 | MUST | Между стадиями pipeline не должно быть обязательного возврата полного кадра на CPU. | Профиль не показывает full-frame readback. |
| SRV-G-003 | MUST | CPU reference должен существовать отдельно от production GPU path. | Golden test сравнивает одинаковые входы. |
| SRV-G-004 | MUST | Сервер должен измерять GPU time отдельных render stages. | Доступны timer-query или эквивалентные измерения. |
| SRV-G-005 | SHOULD | Контекст GPU должен создаваться без Qt Widgets. | Server запускается в headless-конфигурации. |

## Серверные ограничения

- UI-код Qt Widgets запрещен в модуле обработки.
- Размеры автомобиля, калибровка, количество камер и параметры поверхности не должны быть hardcoded.
- Ошибка одного источника не должна блокировать прием остальных источников.
- Render thread не должен ждать бесконечно сетевой или файловый ввод.
