# Нефункциональные требования и метрики

## Назначение и статус

Редакция от 19.09.2026. Требования исследовательского ядра и полного локального стенда. Числа ниже — предварительные инженерные цели из аудита, не результаты измерений и не универсальные автомобильные нормативы. После раннего baseline и до итогового сравнения они фиксируются в версии паспорта [VALIDATION.md](../VALIDATION.md); изменение порогов отражается явно. Связанные решения: [ADR](../SYSTEM_ARCHITECTURE.md), [исследование](../RESEARCH_PLAN.md).

## Профиль и определения

Исходный `local-reference`: один Linux-узел, replay четырёх RGB8/sRGB потоков 1280×720 по 30 FPS, выход RGBA8/sRGB 1280×720; CPU, GPU, драйвер, ОС, сборка, сетка и экран записываются в паспорт до измерений. Один набор имеет frame_set_id; отдельные новые ракурсы того же набора не увеличивают счётчик уникальных входных наборов. Полноразмерный сетевой режим из этого профиля не следует.

В локальном опыте `t_release` — выпуск replay-входа в текущем clock domain, `t_present_submit` — событие Qt Quick о передаче использованного кадра на представление [1]. Программная сквозная задержка = `t_present_submit − min(t_release_i)` по реально использованным входам. Возраст набора в событии t = `t − min(t_input_i)`; skew = `max(t_input_i) − min(t_input_i)`. Для live `t_input` означает захват; для replay — выпуск, а исходное время сценария сохраняется отдельно.

Отклик команды = время первого `ui_present_submit` результата, включающего принятую команду, минус время UI-события этой команды. Используются command_id, state_revision и frame_id. Ни получение кадра, ни ACK команды не заменяют этот конец измерения. Шкалы разных компьютеров требуют преобразования с погрешностью [2]. Физическая задержка до появления пикселя не заявляется без внешнего измерителя.

|---|---|---|---|---|
| NFR-P-001 | MUST | На local-reference учитываются input, accepted sets, rendered и представленные уникальные наборы. | T-NFR-P01: устойчивый прогон 10 мин, номинал 30 наборов/с, доля пропущенных ожидаемых наборов ≤1%; повторы отдельно. | R6 |
| NFR-P-002 | MUST | Измеряется полный программный путь от выпуска входа до ui_present_submit с известным clock domain. | T-NFR-P02 и T-SYS-006: p50/p95/p99/max; исходная цель p95 ≤100 мс локально. | R6 |
| NFR-P-003 | MUST | Измеряются CPU submission, GPU execution, readback, IPC, upload UI, интервалы кадров, память и очереди. | T-NFR-P03: неблокирующие timer queries, trace и p50/p95/p99/max; исходный p95 GPU ≤20 мс. | R6 |
| NFR-P-004 | MUST | Изменение только виртуального вида использует готовые сетку, калибровку и входные текстуры. | T-NFR-P04 / T-UI-004: 500 команд на PAUSED-наборе, счётчики decode/upload входа/mesh rebuild неизменны. | R5 |
| NFR-P-005 | SHOULD | Для принятого режима задаётся дополнительный предел нестабильности интервала уникальных представлений. | T-NFR-P05: jitter = p95(interval)−p50(interval); предел фиксируется по baseline до итоговых опытов. | R6 |
| NFR-P-006 | MUST | Каждая принятая команда связывается с первым представленным результатом, включающим её ревизию. | T-NFR-P06 / E-INTERACTIVE-01: p50/p95/p99/max отклика, исходная цель p95 ≤100 мс; исключённые команды с причиной. | R5, R6 |

GPU-бюджет не является бюджетом полной системы. Sweep: прогрев 60 с и минимум три независимых прогона по 180 с; устойчивый режим — отдельный десятиминутный прогон. Сохраняются максимальные паузы, причина каждого класса потерь и разброс между прогонами. Для доли пропущенных наборов фиксируется ожидаемая последовательность выпуска manifest; при faults потери producer и сервера считаются отдельно.

|---|---|---|---|---|
| NFR-Q-001 | MUST | Ошибка прямой GPU-проекции относительно независимого CPU оценивается в валидной области. | T-NFR-Q01 / E-MATH-01: p99 UV ≤0,1 пикселя входа; максимум и ошибки валидности отдельно. | R2 |
| NFR-Q-002 | MUST | Ошибка дискретизации измеряется отдельно от калибровки и условной модели сцены. | T-NFR-Q02 / E-MESH-01: исходный p99 UV ≤0,5 пикселя входа; p99 экрана ≤0,5 пикселя выхода на отложенных видах; максимумы публикуются. | R4 |
| NFR-Q-003 | MUST | Для заранее заданной физически покрываемой контрольной конфигурации измеряется покрытие ROI вне автомобиля/фона. | T-NFR-Q03: исходная цель ≥99%, площадь ROI и heatmap; области без наблюдения отмечены. | R3 |

Эти допуски не означают доказанного глобального максимума. Допуск суммы весов нормативно задан в SRV-F-007. Яркостный шов, ошибка маркеров и двоение вертикальных объектов — разные показатели E-SURFACE-01; обещание «без швов» отсутствует.

| NFR-R-003 | MUST | Ошибка конфигурации, транспорта или GPU имеет код и источник; невалидный вход не становится валидным кадром. | T-NFR-R03: ошибки запуска и payload, ERROR с причиной. | R5 |

PAUSED/static исследовательский режим сохраняет изображения с явной маркировкой и реальным возрастом; его метрики не выдаются за свежесть live-потока. Глубины и пределы ресурсов указаны в CONFIGURATION/PROTOCOL.

Старые ID сохранены как указатели: NFR-C-001 → SYS-F-003/CFG-F-002…005; NFR-C-002 → CFG-F-008; NFR-C-003 → SRV-F-012; NFR-R-004 → OPS-F-009; NFR-M-002 → OPS-F-001; NFR-M-003 → PRO-F-003; NFR-M-004 → SRV-G-003 (MUST). Отдельно принимать эти дубли не требуется. Паспорт платформы и все наблюдаемые результаты находятся в [VALIDATION.md](../VALIDATION.md).
