# Нефункциональные требования и метрики

## Назначение и статус

Рабочая редакция от 06.10.2026; основа от 19.09.2026. Требования исследовательского ядра и полного локального стенда. Числа ниже — предварительные инженерные цели из аудита, не результаты измерений и не универсальные автомобильные нормативы. После раннего baseline и до итогового сравнения они фиксируются в версии паспорта [ACCEPTANCE.md](../validation/ACCEPTANCE.md); изменение порогов отражается явно. Связанные решения: [[architecture/DECISIONS|ADR]], [исследование](../research/EXPERIMENTS.md).

## Профиль и определения

Исходный `local-reference`: один Linux-узел, replay четырёх RGB8/sRGB потоков 1280×720 по 30 FPS, выход RGBA8/sRGB 1280×720; CPU, GPU, драйвер, ОС, сборка, сетка и экран записываются в паспорт до измерений. Один набор имеет frame_set_id; отдельные новые ракурсы того же набора не увеличивают счётчик уникальных входных наборов. Полноразмерный сетевой режим из этого профиля не следует.

В локальном опыте `t_release` — выпуск replay-входа в текущем clock domain, `t_present_submit` — событие Qt Quick о передаче использованного кадра на представление [[references/DEVELOPMENT#S49|S49]]. Программная сквозная задержка = `t_present_submit − min(t_release_i)` по реально использованным входам. Возраст набора в событии t = `t − min(t_input_i)`; skew = `max(t_input_i) − min(t_input_i)`. Для live `t_input` означает захват; для replay — выпуск, а исходное время сценария сохраняется отдельно.

Отклик команды = время первого `ui_present_submit` результата, включающего принятую команду, минус время UI-события этой команды. Используются command_id, state_revision и frame_id. Ни получение кадра, ни ACK команды не заменяют этот конец измерения. Шкалы разных компьютеров требуют преобразования с погрешностью [[references/MEASUREMENT#S48|S48]]. Физическая задержка до появления пикселя не заявляется без внешнего измерителя.

| NFR-P-006 | MUST | Каждая принятая команда связывается с первым представленным результатом, включающим её ревизию. | T-NFR-P06 / E-INTERACTIVE-01: p50/p95/p99/max отклика, исходная цель p95 ≤100 мс; исключённые команды с причиной. | R5, R6 |

GPU-бюджет не является бюджетом полной системы. Sweep: прогрев 60 с и минимум три независимых прогона по 180 с; устойчивый режим — отдельный десятиминутный прогон. Сохраняются максимальные паузы, причина каждого класса потерь и разброс между прогонами. Для доли пропущенных наборов фиксируется ожидаемая последовательность выпуска manifest; при faults потери producer и сервера считаются отдельно.

## Качество и численная точность

| ID | Приоритет | Условие и наблюдаемое поведение | Приёмка и исходная цель | Задача |
|---|---|---|---|---|
| NFR-Q-001 | MUST | Ошибка прямой GPU-проекции относительно независимого CPU оценивается в валидной области. | T-NFR-Q01 / E-MATH-01: p99 UV ≤0,1 пикселя входа; максимум и ошибки валидности отдельно. | R2 |
| NFR-Q-002 | MUST | Ошибка дискретизации измеряется отдельно от калибровки и условной модели сцены. | T-NFR-Q02 / контроль равномерной сетки и, при включении, E-MESH-01: исходный p99 UV ≤0,5 пикселя входа; p99 экрана ≤0,5 пикселя выхода на отложенных видах; максимумы публикуются. | R4 |
| NFR-Q-003 | MUST | Для заранее заданной физически покрываемой контрольной конфигурации измеряется покрытие ROI вне автомобиля/фона. | T-NFR-Q03: исходная цель ≥99%, площадь ROI и heatmap; области без наблюдения отмечены. | R3 |

Эти допуски не означают доказанного глобального максимума. Допуск суммы весов нормативно задан в SRV-F-007. Яркостный шов, ошибка маркеров, двоение вертикальных объектов и временная стабильность seam — разные показатели E-SURFACE-01/E-STITCH-01; обещание «без швов» отсутствует. Алгоритм, который улучшает один показатель ценой другого, должен быть описан вместе с условиями и бюджетом.
