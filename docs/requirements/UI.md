# Требования к `sv-ui`

## Ответственность

`sv-ui` — Qt5-приложение головного устройства. Оно показывает результат сервера и отправляет пользовательские команды.

## Функциональные требования

| ID | Приоритет | Требование | Приемка |
|---|---|---|---|
| UI-F-001 | MUST | UI должен подключаться к `sv-server` при запуске. | Состояние `connected/disconnected/reconnecting` отображается. |
| UI-F-002 | MUST | UI должен отображать последний валидный `rendered_frame`. | Кадр не искажается при поддержанном pixel format. |
| UI-F-003 | MUST | UI должен преобразовывать touch drag в `orbit` или `pan`. | Жест изменяет соответствующий параметр на сервере. |
| UI-F-004 | MUST | UI должен преобразовывать pinch/эквивалент в `zoom`. | Масштаб/дистанция виртуальной камеры изменяется. |
| UI-F-005 | MUST | UI должен поддерживать фиксированные camera presets. | Команда preset подтверждается `camera_state`. |
| UI-F-006 | MUST | UI должен показывать latency, FPS, drops и состояние источников. | Данные берутся из server telemetry, не вычисляются приблизительно. |
| UI-F-007 | MUST | UI должен показывать понятное состояние при потере сервера. | Нет зависшего кадра без индикатора устаревания. |
| UI-F-008 | SHOULD | UI должен позволять выбрать diagnostic view камеры или weight mask. | Режим меняется без изменения server algorithms. |

## Ограничения UI

- Реализация должна использовать Qt5.
- UI не выполняет fisheye correction, calibration, blending или генерацию bowl-сетки.
- UI не является владельцем состояния виртуальной камеры.
- UI не должен блокировать главный event loop сетевым чтением или ожиданием кадра.
- Визуальные размеры и частота обновления должны соответствовать целевому экрану головного устройства.

## Приемочный сценарий

1. Запустить сервер с mock frame.
2. Запустить UI и дождаться `connected`.
3. Убедиться, что кадр отображается.
4. Выполнить drag и проверить изменение `camera_state`.
5. Остановить сервер и проверить диагностическое состояние.
