# Требования к `sv-client`: Qt Quick (QML)

## Назначение и статус

Рабочая редакция от 05.10.2026; основа от 19.09.2026. Планируемый тонкий клиент на Qt версии из паспорта платформы, Qt Quick (QML) и QML-модули, проверенные для данного профиля [[references/DEVELOPMENT#S45|S45]]. Вход — готовый кадр сервера; выход — команды ракурса и события UI. Решения: [[architecture/DECISIONS|ADR-002/012]], [протокол](PROTOCOL.md), [конфигурация камеры](CONFIGURATION.md), [приёмка](../validation/ACCEPTANCE.md). Подмножество UI реализовано в 0.2.0; выделение клиентской библиотеки и удалённое подключение относятся к следующему этапу.

## Клиентская библиотека sv-client-lib (план)

`sv-client-lib` — отдельная C++17-библиотека, первый потребитель — `sv-client`. Здесь закреплён будущий контракт, не существующий CMake target или новые поля JSON 0.2.0. API описывает подключение к серверу, команды и готовые результаты; рендеринг, GPU и Qt Quick остаются в своих компонентах. Подробный порядок реализации — [[planning/ROADMAP#Следующий этап: источники, удалённое управление и 3D-окружение]].

Планируемые операции API: подключиться/отключиться, завершить асинхронную работу, отправить команду, получить ACK/reject, подписаться на состояния и кадры, освободить результат. Тип endpoint содержит либо пути Unix-каналов, либо TCP host и два порта; transport-specific детали остаются внутри адаптеров. Выбор транспорта не меняет модель команд и метаданных. Имена C++ классов и числовые TCP defaults закрепляются при реализации вместе с серверной схемой.

Библиотека фиксирует собственные receive times и сохраняет серверный clock domain. UI самостоятельно формирует `ui_receive`/`ui_present_submit`; преобразование часов удалённого узла проверяется отдельно по [[requirements/PROTOCOL]]. При его отсутствии сквозная latency остаётся недоступной. Физические камеры открывает сервер; клиентская библиотека не перенаправляет `/dev/video*` ноутбука на целевое устройство.

Qt `Bridge` станет адаптером API: переносит callback в UI thread, создаёт собственную QImage-копию и отправляет release, связывает свойства/сигналы с QML. Для будущего удалённого конфигуратора можно использовать тот же C++ API; bindings для нынешнего Python offline-конфигуратора — отдельное решение. Общий wire codec выделяется из существующего протокола и переиспользуется сервером/библиотекой. Реализацию сетевого профиля на сервере выполнять вместе с TCP-адаптером библиотеки.

## Представление и потоки

Приложение создают `QGuiApplication` и `QQmlApplicationEngine`. В QML находятся окно, кнопки пресетов, жесты и оверлеи. Qt-адаптер `sv-client-lib` передаёт готовые кадры собственному `QQuickItem` с `QSGTexture`; ресурсы отображения создаются и удаляются согласно потоку Qt Quick scene graph [[references/DEVELOPMENT#S47|S47]]. Это проектный путь: в 0.2.0 используется QQuickImageProvider и прямой QLocalSocket `Bridge`, см. [[prototype/STATUS]]. Чтение сокета в библиотеке выполняется асинхронно, очередь кадров ограничена. Серверные UV, bowl и blending остаются в `sv-core`.

Событие `ui_receive` отмечает получение; `ui_present_submit` — сигнал `QQuickWindow::frameSwapped` с ID кадра, выбранного scene graph [[references/DEVELOPMENT#S49|S49]]. Сигнал не доказывает физический момент появления пикселя на экране. Если scene graph повторяет старую текстуру, это повтор кадра, а не новый набор. Если интерфейс скрыт и сигнал не приходит, latency не подставляется из времени получения.

Для каждой принятой команды сохраняется ID и первая ревизия, в которую она вошла. ACK подтверждает обработку команды; отклик завершается первым представлением результата, включающего эту ревизию. При объединении delta-команд сохраняется перечень ID и состав ревизии. Недоступное измерение показывается как недоступное, а не как нулевое.

## Допустимые ракурсы и свежесть

Orbit задаёт азимут, угол возвышения и расстояние до фиксированной цели; zoom меняет расстояние. Диапазоны, near/far, запас над поверхностью, габариты автомобиля и допустимые пресеты задаются в CONFIGURATION. Сервер ограничивает или отклоняет недопустимое состояние и сообщает причину. Pan — COULD; при реализации ограничивается рабочей областью и той же проверкой столкновений.

UI может сохранять последний кадр при потере связи только с постоянно видимым индикатором устаревания. Свежесть определяется возрастом набора и давностью последнего получения по текущей шкале, по более строгому из ограничений. На явной паузе replay кадр маркируется PAUSED и сохраняет фактический возраст; live-поток не получает это исключение. Маски недоступных камер приходят с серверным кадром.

## Приёмочный сценарий

1. Запустить server с фиксированным набором и UI; проверить handshake и изображение маркеров.
2. Включить паузу replay, выполнить 500 команд orbit/zoom/preset и сопоставить их с кадрами.
3. Проверить ограничения камеры и отсутствие новых upload входа/перестроений сетки; upload готового изображения UI считается отдельно.
4. Отключить камеру, затем сервер; проверить DEGRADED, маски и stale-overlay.
5. Перезапустить сервер, проверить новую сессию и восстановление; сохранить trace UI и сервера.
6. Повторить сценарий с тем же UI через `sv-client-lib`: сначала Unix, затем TCP loopback и сервер на другом устройстве. Сохранить endpoint, версии и раздельные clock domains; локальные и сетевые времена публиковать отдельно.
7. Собрать headless consumer из installed CMake package; проверить библиотеку без QML и повторить отказные сценарии CLIB-F-003…007.
