# Архитектурные решения и открытые вопросы

Статус «проектное» означает решение для реализации и проверки, «требует проверки» — зависимость от оборудования или внешних условий. «Проверено на Linux» относится только к именованному настольному профилю, а не к Авроре или всем требованиям. Свидетельства — [[prototype/STATUS]] и [[prototype/MEASUREMENTS]] от 05.10.2026. Контракты компонентов: [[requirements/SYSTEM]].

| ID | Статус | Решение | Что проверить / когда пересмотреть |
|---|---|---|---|
| ADR-001 | Требует проверки | Целевая платформа — ОС Аврора; Linux — начальный replay/benchmark-стенд. Один графический профиль выбирается по реальному устройству | CPU/GPU, ОС/SDK, Qt, компилятор, EGL, OpenGL ES, extensions, headless и доступ к GPU. Прежний OpenGL 3.3/GLSL 330 — desktop-кандидат |
| ADR-002 | Проектное для начального стенда | Копируемый выход FBO → CPU → локальный IPC → текстура клиента; отдельный control channel | Readback, копии, upload и полная latency. DMA-BUF вводить при измеренном ограничении и поддержке платформой |
| ADR-003 | Проектное | На одном узле общий monotonic domain; replay сохраняет исходное время и runtime mapping | На нескольких узлах требуется преобразование часов с оценкой погрешности; без него сквозная latency недоступна |
| ADR-004 | Проектное | `sv-core` без Qt и транспорта; клиент называется `sv-client`; `sv-configurator` — offline-приложение рабочей станции | C++/OpenCV/математические зависимости для устройства; изоляция Qt в клиенте; отсутствие зависимости GPU-пути от конфигуратора |
| ADR-005 | Проектное | Одна точная модель `opencv_fisheye`, передняя полусфера; плоскость и аналитическая bowl как baseline | Независимые контрольные точки и соответствие доступным камерам. Другие поверхности добавлять после сравнения базовых |
| ADR-006 | Проектное | Первоначальная/повторная калибровка по шаблону; диагностика перекрытий не применяет параметры автоматически | Проверочные наблюдения, наблюдаемость, ложные срабатывания; новая калибровка применяется атомарно между запусками |
| ADR-007 | Проектное | Один источник истины для каждого типа документа; Markdown и встроенный PlantUML | Правила [[README\|карты документации]], валидные ссылки и прослеживаемость переноса |
| ADR-008 | Проверено на Linux, 05.10.2026 | C++17; системная GLM 1.0.3 для RH view/perspective, FetchContent той же версии как fallback; Boost.JSON для данных, один Boost.Asio runner и один GL-владелец | Сборки GPU/CPU, независимые точки и IPC пройдены. Для Авроры проверить зависимости. Добавлять worker pool после выделения FrameSource и измерения декодирования |
| ADR-009 | Проверено на Linux, 05.10.2026 | EGL/GLES 3: Mesa surfaceless и NVIDIA device platform; copied RGBA и QQuickImageProvider для desktop-проверки | Renderer подтверждён в отчётах, Qt-путь проверен offscreen. Float-FBO зависит от расширения; UI hardware latency, GPU timer queries и target-backend остаются открытыми |

ADR-002, ADR-004 и ADR-005 получили частичные свидетельства Linux-профиля: копируемый IPC, граница ядра и контрольные проекции. Их полные критерии, включая физическую задержку, реальные камеры и целевой профиль, ещё не закрыты. ADR-006 пока реализован только по известным пространственным соответствиям, без детектора снимков шаблона.

## Первые решения, которые нужно закрыть

- Какое именно устройство доступно, версия Авроры/SDK и сроки доступа?
- Может ли `sv-server` получить GPU-контекст отдельным процессом на устройстве? Какой EGL backend разрешён?
- Какие версии C++, Qt и графического API поддерживаются? Доступны ли OpenCV, нужные Qt/QML-модули и пакетирование зависимостей?
- Как передавать четыре входа: файлы/replay, локальный захват или сетевой producer? Какова полоса и цена декодирования?
- Какие реальные калибровочные записи и шаблоны доступны? Достаточны ли перекрытия для выбранной диагностики?
- Какой срок защиты и бюджет работы? Календарь [[planning/ROADMAP]] привязывается к ним после технической разведки.

## Паспорт решения

При закрытии ADR записать дату, платформу, проверочный сценарий, наблюдаемые значения, ссылку на Markdown-отчёт и причину выбора. При изменении профиля обновить конфигурацию, NFR и приёмку. Не повышать версию графического API ради функций, которые не нужны основному конвейеру.
