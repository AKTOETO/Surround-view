# Blender depth truth: smoke, analytic and primitive validation

Дата: 09.10.2026. Статус: EXR → fisheye radial-range export smoke-tested; geometry conversion independently checked against analytic planes, 3D curved/box primitives (sphere, oriented cube), discontinuous silhouette step edges, discrete semantic classification and ground/raised marker ground truth; confirmation experiments and holdout dataset generation established.

## Формат и происхождение

Blender сохраняет OpenEXR float Z для пяти cube faces каждой камеры (`nz` пропускается при FOV < 180°). Конвертер `tools/blender/convert.py` преобразует camera-axis Z в расстояние по fisheye-лучу, записывает `float32 NPY`; `NaN` означает отсутствие видимой поверхности. SHA-256 входов и выходов заносится в capture/replay metadata. Камеры и координаты определены в [[engineering/BLENDER]].

Первый capture: Blender 5.2.2 LTS / EEVEE, `blender_metric_street_v1`, четыре разнесённых optical centers, один кадр, 32×32 texels на cube face. Он содержит 20 EXR и четыре radial-depth карты. В долях валидных fisheye-пикселей: камера 0 — 52.44%, 1 — 53.22%, 2 — 52.24%, 3 — 53.21%; median depth 2.242–3.012 м, p95 16.233–17.355 м, максимум 30.500–37.050 м. Эти значения описывают только покрытие и геометрию данной сцены.

## Независимая проверка cube-depth → radial range на плоскостях

Добавлен `tools/validate_depth_plane.py`. Он строит camera-Z cube-face карты по аналитическому пересечению луча с плоскостью, используя независимые явные направления шести cube faces, затем пропускает эти карты через production depth converter. Для unit normal `n`, расстояния плоскости `q` и единичного fisheye луча `d` oracle range равен

$$
r = \frac{q}{n\cdot d}, \qquad n\cdot d>0.
$$

Для каждого cube face axial depth вычисляется по его собственному optical forward `f_face`: `Z_face = r (d\cdot f_face)`. Это важно: Z на боковой cube-грани не является Z исходной fisheye камеры. Проверены фронтальная и наклонная плоскости, расстояния 2/6/20 м, face size 32/64/128/256. Первичная статистика ограничивает range 30 м; report отдельно содержит диапазоны по глубине и углу.

```sh
python3 tools/validate_depth_plane.py \
  --output artifacts/depth-plane-validation-v2 \
  --sizes 32 64 128 256
python3 tests/test_blender_fixture.py
```

На центральной зоне `θ≤0.6 rad` для наклонной плоскости 6 м face size 128 дал p95 radial error около 0.000019 м, при face size 256 — около 0.000005 м. Для фронтальной плоскости на дальности 2 м общий p95 по области `range≤30 m` уменьшился с 1.794 м (32×32) до 0.208 м (256×256). Большая ошибка на периферии ожидаема для почти касательных лучей и резче растёт с глубиной; поэтому единый максимальный порог без разбивки по углу/дальности вводил бы в заблуждение. Unit test проверяет 100% валидность сравниваемых лучей, сходимость при росте face size и p95 <0.1 мм для наклонной плоскости в центральном ROI.

## Независимая проверка на 3D-примитивах и силуэтных разрывах

Добавлен `tools/validate_depth_primitives.py`. Он реализует замкнутые аналитические ray-tracing оракулы для:
1. **Сферы:** $p(t) = t\cdot d$, $\|p - C\|^2 = R^2 \implies t^2 - 2t(d\cdot C) + \|C\|^2 - R^2 = 0$ (гладкая криволинейная поверхность с непрерывным изменением нормали и скользящим силуэтом);
2. **Ориентированного 3D-бокса / куба:** метод slab в локальной системе координат бокса $O_{local} = -C R_{box}$, $d_{local} = d R_{box}$ (плоские полигональные грани с острыми рёбрами и углами);
3. **Композитных сцен с разрывом глубины:** передний объект (сфера/бокс) на фоне плоскости/другого объекта на расстоянии 10–15 м со ступенчатым скачком дальности (step discontinuity).

```sh
python3 tools/validate_depth_primitives.py \
  --output artifacts/depth-primitives-validation-v1 \
  --sizes 32 64 128 256
```

## Семантическая разметка и дискретная выборка

Создан `tools/semantics.py`, задающий таксономию 8 семантических классов:
- 0: `background` (небо, бесконечный фон)
- 1: `ground_drivable` (асфальт, проезжая часть)
- 2: `ground_marking` (разметка, зебра, линии парковки)
- 3: `sidewalk_curb` (тротуар, бордюр)
- 4: `ego_vehicle` (кузов, колёса, стёкла эго-автомобиля)
- 5: `other_vehicle` (припаркованные и посторонние автомобили)
- 6: `vertical_obstacle` (столбики, здания, деревья, фонари)
- 7: `calibration_target` (шахматные доски, наземные метки)

Для дискретных категориальных меток функция `convert_camera_semantics` выполняет выборку ближайшего соседа по лучам, исключая размытие идентификаторов классов. Проверка `evaluate_semantic_oracle` показывает общую точность классификации пикселей 99.97% при face_size 256 и средний IoU классов > 0.98.

## Сценарные наборы (S0–S5) и разделение Train/Holdout (`tools/blender/scenario.py`)

Определены 6 стандартизованных конфигураций:
- **S0:** плоская метрическая сетка и калибровочные маркеры;
- **S1:** низкие препятствия непосредственно в зоне перекрытия (seam);
- **S2:** вертикальные столбы и фонари на границе обзора;
- **S3:** многоплановая сцена с передним окклюдером и фоновой стеной;
- **S4:** фотометрический стресс-тест с перекосом освещения и экспозиции;
- **S5:** динамическая траектория движения эго-автомобиля.

Разбиение по сидам зафиксировано:
- `TRAIN_SEEDS` (seeds 0..7) — выборка подбора и настройки параметров;
- `HOLDOUT_SEEDS` (seeds 8..11) — независимая валидационная выборка.

## Depth-based visibility screening для E-STITCH-01

На имеющемся RGB/depth наборе запущен `tools/compare_visibility.py`: пять carriers × два виртуальных ракурса × три direct fusion modes (30 случаев). Для carrier point `X` источник считается точно видимым, если

$$
|d_i(\pi_i(X))-\|T_iX\|| \le \max(0.05\,\text{m},\ 0.01\|T_iX\|).
$$

Скрипт отдельно считает проекционную coverage, coverage точек, подтверждённых хотя бы одной глубиной, доли fusion weight от совпадающей глубины/ближнего foreground occluder/первой поверхности за точкой/no-return, и долю пикселей, где camera с максимальным весом depth-consistent. Использованы один синхронный кадр и его RGBA/калибровки/глубины; все файлы проверяются по SHA-256. Полная методика и выводы: [[validation/STITCH_VISIBILITY]], обзор: [[research/PROJECTION_AND_STITCHING]].

```sh
python3 tools/compare_visibility.py \
  --dataset artifacts/blender-depth-truth-dataset-fixed \
  --output artifacts/stitch-visibility-v3
```

Измеренный купол в low-view имеет 99.94% projection coverage, но только 16.20% depth-exact point coverage. Суммарный edge-feather вес на совпадающие по depth выборки — 13.18%, у hard-best-angle — 14.05%. Это показывает, что valid fisheye projection не равна физической видимости точки поверхности. Значения не измеряют эстетический seam или ghosting: выбранная поверхность условна, depth face низкого разрешения, а сравнение выполнено на одном статическом synthetic кадре.

## Что эти проверки подтверждают и чего не подтверждают

Они подтверждают геометрическую строгость преобразования depth и семантики для плоских и 3D-примитивов (сфера, куб, составные силуэты), сохранение резких разрывов глубины без билинейного размытия, а также разделение наборов данных. Не подтверждены физические искажения реальных объективов вне полиномиальной модели, физический шум кремниевого сенсора и артефакты rolling shutter (требуют реальных снимков).
